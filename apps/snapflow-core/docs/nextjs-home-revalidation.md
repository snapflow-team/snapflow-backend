# Ревалидация главной (Next.js API route)

## Что происходит

Бэкенд **иногда** шлёт `POST` на ваш фронт, чтобы обновить кэш главной. Вызовы **сжаты**: не после каждого поста и не после каждой регистрации, а когда с прошлого **успешного** запроса накопится **или** достаточно новых постов (**4**), **или** достаточно новых регистраций (**5**).

## Контракт для фронта

| Что | Значение |
|-----|----------|
| Метод | `POST` |
| Путь | `/api/revalidate-home` |
| Host | тот же публичный URL фронта, что в `BASE_FRONT_URL` на бэкенде |
| Заголовок | `Authorization: Bearer <JWT>` |
| Тело | `{}` |

**JWT:** проверка подписью общим секретом `NEXTJS_REVALIDATION_SECRET` (на фронте — для `verify`, на бэке — для `sign`). В payload должен быть claim:

```json
{ "action": "revalidate_home" }
```

Проверяйте подпись, срок жизни и что `action === "revalidate_home"`. Дальше — `revalidatePath('/')` / ваши теги для главной.

**Ответ:** отдайте **2xx**, если ревалидация прошла (так бэкенд зафиксирует успех). Иначе бэкенд повторит запрос позже.

## Переменные

Один секрет у обеих сторон: **`NEXTJS_REVALIDATION_SECRET`**. TTL токена на бэкенде задаётся **`NEXTJS_REVALIDATION_TOKEN_EXPIRES_IN`** — фронт при верификации должен использовать совместимые правила времени жизни.

Алгоритм подписи JWT должен совпадать с бэкендом (те же параметры генерации).
